# 桃花小签：规则驱动的 AI 解读

## 来源与范围

采用[《三命通会》卷三](https://www.chinese-classics.org/read/shushu/mingli/san-ming-tong-hui/003)中的咸池桃花规则：申子辰对应酉，寅午戌对应卯，巳酉丑对应午，亥卯未对应子。古籍是民俗规则来源，不是预测有效性的科学证据；不沿用其中的道德、性别或灾祸判断。转录中的“己酉丑”按地支“巳”处理。

## 当前实现

按产品要求，推算和解释交给真实 AI，程序不维护桃花映射表，也不根据本地规则生成结果。

1. 页面收集用户确认的公历出生日期、出生时间（可未知）、出生地、感情状态、所查流年和可选补充问题。
2. `bootstrap.py` 读取 `backend/agents/rules/romance.md`，注入独立的 `RomanceAgent`。
3. Agent 把可信规则作为系统消息，用户资料作为单独的数据消息，通过已有 `LanguageModel.stream` 调用当前配置的模型。
4. `POST /api/romance/calculate` 返回 SSE，页面实时渲染 Markdown，支持停止、重试；修改输入会取消并清除旧结果。

输入模型 `backend/domain/romance.py` 仅校验日期、时分、出生地、感情状态、流年范围和补充文本长度。没有查询结果持久化、匹配分调整或假数据兜底。模型不可用、空输出或流中断时显示错误。

这是一次规则驱动的模型分析调用；没有虚构工具执行日志，也没有把它描述成具备历法工具的多轮自主排盘 Agent。页面显示的依据是模型给出的公开说明，不是内部思维链。

## 规则文件包含什么

规则版本为 `xianchi-agent-v3`。除咸池规则外，还提供1984甲子周期锚点、天干地支顺序、立春换年口径和输出约定。AI 自行推算四柱参考与流年，分别说明输入、规则、结论与资料局限。后端不校验命理推算是否正确，因此可能存在模型计算误差。

输入统一按公历、北京时间 UTC+8 和民用午夜换日口径处理，不做真太阳时和历史夏令时修正。AI 依据出生资料给出四柱参考，不能确定的字段需标“待核实”，不用于确定性结论；时间未知时不填写时柱。未经核实的红鸾、天喜、大运算法不加入当前规则，禁止随意加权为脱单概率。

## 模型与资料

复用 `config.yaml` 的模型配置与 API Key。该模块会消耗正常模型额度；用户提交的信息会发送给所配置的外部模型服务，本应用不将其写入本地数据库。不能宣传为“资料始终留在本机”。

这是民俗娱乐，不代表科学预测，不影响候选推荐或约会决策。

## 验证

测试检查规则和用户数据确实交给模型、文字分片转发、空输出报错与上游错误不回退成本地计算。真实模型联调使用虚构出生资料与问题，不使用私人出生信息。前端构建和类型检查不能替代浏览器视觉验收。

## 演示模板

点击“填入示例”可填入公历2000-06-15、北京时间14:30、浙江杭州、单身、关注2026年。该资料为虚构演示输入，回复仍实时调用真实模型，不是预置报告。页面保持固定高度并分别滚动，详细口径折叠展示。

## 今日结论展示

后端为每次调用注入北京时间的 `today`，与用户关注的流年 `year` 分开。提示词要求先给“今日桃花”大标题和一句结论，再给三条行动建议，最后呈现依据。今日状态是民俗背景下的娱乐性行动建议，当前没有经过验证的流日算法，不宣称计算了精确流日吉凶。前端突出一级标题和结论引用块。
