# 可共享的虚构候选数据

`candidates.json` 是完整的数据源，随 Git 仓库一起分发，不依赖原作者电脑上的 SQLite 文件，也不需要调用模型生成数据。全部人物为合成的课设示例，不代表真实用户；不包含照片、联系方式或聊天记录。

当前数据版本：`2026-09-09.1`，结构版本：`1`。

- 1,200 位人物，年龄 18–60 岁；原始 1–120 号人物保持不变，新增 121–1200 号。
- 20 个城市：杭州、上海、北京、沈阳、成都、广州、深圳、南京、苏州、武汉、西安、重庆、长沙、厦门、青岛、天津、郑州、合肥、昆明、大连。
- 10 类兴趣，新增人物每人 2–5 项；包含不同生活节奏、关系目标、见面频率和饮食偏好，预算为 50–300 元。
- 数据为演示而构造，城市数量和年龄比例不代表现实人口分布。相似姓名或介绍不表示真实身份关系。

## 别人拉取仓库后怎么运行

按根目录 [README](../README.md) 安装依赖、创建自己的 `config.yaml`，然后运行启动脚本。后端自动从此 JSON 导入本机 SQLite，无需 SQL 导入工具、数据库服务或原作者的 API Key。

新机器首次运行会导入全部 1,200 位。旧机器更新代码和数据后，重启后端即可补齐新增人物；原有聊天、选择记录和已存在的人物不会被覆盖。数据文件使用相对项目位置定位，不依赖 `/Users/...` 路径。数据库实际位置由运行配置决定，默认是 `data/yuanxi.db`。

## 后续增加或修改数据

直接编辑 JSON 的 `candidates` 数组并更新 `dataset_version`。新增人物使用从未使用过的正整数 ID，不要复用或修改旧 ID。保持现有字段与分类格式；加载器会校验字段、年龄、预算和 ID 唯一性，校验失败时不会开始导入。

导入是**只补齐缺失 ID**：修改或删除 JSON 中已有 ID 不会改动已有数据库。这个约定用于保留本地修改及旧会话引用，不支持通过更改版本号强制覆盖。新数据库会获得 JSON 中的最新内容。如需比较新的完整快照，可在本地配置中指定新的数据库路径，再重启；不要删除包含私人聊天的旧数据库。

提交时包含 `datasets/` 和配套后端代码、文档。`config.yaml`、`.env`、SQLite 数据库及其日志仍由 `.gitignore` 排除，不能作为共享数据上传。模型密钥由每位使用者自行配置。

验证命令（仓库根目录）：

```sh
.venv/bin/python -m unittest discover -s backend/tests -v
```
